故障排除

常见问题诊断

快速诊断检查清单

  1. 检查插件状态

    确认插件已激活且没有错误提示

  2. 验证配置常量

    确认 FD_WEBSOCKET_PUSH_SECRET 和 REVALIDATE_SECRET 已正确定义

  3. 检查错误日志

    查看 WordPress 错误日志中的相关消息

  4. 测试网络连接

    确认 WordPress 能够访问 WebSocket 服务器和前端服务器

  5. 验证服务状态

    确认 WebSocket 服务器和 Next.js 前端正常运行

配置相关问题

❌ 问题：插件激活后没有任何反应

可能原因：

  • 配置常量未定义或定义错误
  • PHP 版本不兼容
  • 文件权限问题

解决方案：

  1. 检查 wp-config.php 中的常量定义： 
    define( 'FD_WEBSOCKET_PUSH_SECRET', 'your-secret-key' );
define( 'REVALIDATE_SECRET', 'your-revalidate-key' );
  2. 确认 PHP 版本 ≥ 7.4
  3. 检查插件文件权限（建议 644 for files, 755 for directories）
  4. 查看 WordPress 错误日志获取详细信息

❌ 问题：错误日志显示 "SECRET not defined"

错误消息示例：

[Lingcoo WebSocket Push ERROR] FD_WEBSOCKET_PUSH_SECRET not defined
[Lingcoo WebSocket Push ERROR] REVALIDATE_SECRET not defined

解决方案：

  1. 在 wp-config.php 中添加缺失的常量
  2. 确保常量定义在 require_once(ABSPATH . 'wp-settings.php'); 之前
  3. 检查常量值不为空
  4. 重新激活插件

❌ 问题：插件激活失败

可能原因：

  • PHP 语法错误
  • 内存不足
  • 文件缺失或损坏

解决方案：

  1. 检查 PHP 错误日志
  2. 增加 PHP 内存限制：ini_set('memory_limit', '256M');
  3. 重新上传插件文件
  4. 检查文件完整性

WebSocket 推送问题

❌ 问题：WebSocket 事件没有发送

诊断步骤：

  1. 检查错误日志中是否有推送相关消息
  2. 确认 WebSocket 服务器正在运行
  3. 测试网络连接
  4. 验证推送密钥配置

解决方案：

  1. 确认 FD_WEBSOCKET_PUSH_SECRET 与 WebSocket 服务器配置一致
  2. 检查 WebSocket 服务器地址是否正确（默认：http://websocket:8080/push-event）
  3. 确认防火墙没有阻止连接
  4. 检查 WebSocket 服务器日志

❌ 问题：WebSocket 推送失败

错误消息示例：

[Lingcoo WebSocket Push ERROR] WebSocket push failed: Connection timeout

解决方案：

  1. 检查 WebSocket 服务器状态
  2. 验证网络连接和 DNS 解析
  3. 检查服务器负载和响应时间
  4. 考虑增加超时时间

❌ 问题：事件数据不完整

可能原因：

  • 文章元数据缺失
  • 分类法关联问题
  • 权限检查失败

解决方案：

  1. 检查文章的 _fd_short_uuid 元数据
  2. 验证文章的分类法关联
  3. 确认文章类型为公开类型
  4. 检查文章状态和权限设置

缓存失效问题

❌ 问题：前端缓存没有失效

诊断步骤：

  1. 检查 REVALIDATE_SECRET 配置
  2. 确认前端服务器正在运行
  3. 检查缓存失效 API 响应
  4. 验证缓存标签配置

解决方案：

  1. 确认 REVALIDATE_SECRET 与前端配置一致
  2. 检查前端服务器地址（默认：http://frontend:3000）
  3. 验证前端缓存失效 API 端点
  4. 检查前端服务器日志

❌ 问题：缓存失效请求失败

错误消息示例：

[Lingcoo WebSocket Push ERROR] REVALIDATE_SECRET is not defined. Cannot revalidate tag: homepage-posts

解决方案：

  1. 在 wp-config.php 中定义 REVALIDATE_SECRET
  2. 确认常量值与前端应用配置一致
  3. 重新测试缓存失效功能

❌ 问题：分类法索引页文章数量不更新

症状描述：

  • 文章发布/取消发布后，分类页面的文章数量没有更新
  • 标签页面的文章数量显示不正确
  • 自定义分类法页面的文章数量不同步

可能原因：

  • 分类法缓存失效方法未被调用
  • WebSocket事件未发送到分类法页面
  • 前端分类法页面缓存配置问题

解决方案：

  1. 确认插件版本 ≥ 1.0.1（此问题在该版本中已修复）
  2. 检查错误日志中是否有分类法相关的处理记录： 
    [Lingcoo WebSocket Push] Invalidating taxonomy caches for post 123 (reason: post status change)
[Lingcoo WebSocket Push] Invalidating index cache tag: category-index-page
[Lingcoo WebSocket Push] Notifying taxonomy updates for post 123
  3. 验证分类法缓存标签是否正确失效：
    • category-index-page - 分类索引页
    • tag-index-page - 标签索引页
    • taxonomy:custom_taxonomy - 自定义分类法索引页
    • category:slug - 具体分类页
    • tag:slug - 具体标签页
  4. 检查WebSocket事件是否发送： 
    [Lingcoo WebSocket Push] Sending WebSocket event: category:updated
[Lingcoo WebSocket Push] Sending WebSocket event: tag:updated
[Lingcoo WebSocket Push] Sending WebSocket event: taxonomy:updated

测试方法：

  1. 发布一篇带有分类和标签的文章
  2. 检查WordPress错误日志中的处理记录
  3. 访问相关分类法页面，确认文章数量已更新
  4. 将文章改为草稿，再次检查页面更新

❌ 问题：特定页面缓存没有失效

可能原因：

  • 缓存标签配置错误
  • 前端缓存策略问题
  • 网络连接问题

解决方案：

  1. 检查相关的缓存标签是否正确
  2. 手动测试缓存失效 API
  3. 检查前端缓存配置
  4. 验证页面的缓存标签设置

性能相关问题

❌ 问题：WordPress 后台响应变慢

可能原因：

  • WebSocket 请求阻塞
  • 大量事件同时触发
  • 网络延迟过高

解决方案：

  1. 确认所有外部请求都是非阻塞的
  2. 检查 WebSocket 服务器响应时间
  3. 考虑使用队列系统处理大量事件
  4. 优化网络连接

❌ 问题：内存使用过高

解决方案：

  1. 增加 PHP 内存限制
  2. 检查是否有内存泄漏
  3. 优化事件处理逻辑
  4. 考虑使用对象缓存

调试工具和技巧

启用调试模式

在 wp-config.php 中启用调试：

define( 'WP_DEBUG', true );
define( 'WP_DEBUG_LOG', true );
define( 'WP_DEBUG_DISPLAY', false );

查看错误日志

错误日志通常位于：

  • /wp-content/debug.log
  • /var/log/apache2/error.log
  • /var/log/nginx/error.log

手动测试 WebSocket 推送

// 在主题的 functions.php 中添加测试代码
add_action( 'init', function() {
    if ( isset( $_GET['test_websocket'] ) ) {
        $pusher = FD_WebSocket_Push_WebSocket_Pusher::get_instance();
        $result = $pusher->send_event( 'test:event', 'public', [
            'message' => 'Test message',
            'timestamp' => time()
        ] );
        
        if ( is_wp_error( $result ) ) {
            wp_die( 'WebSocket test failed: ' . $result->get_error_message() );
        } else {
            wp_die( 'WebSocket test successful' );
        }
    }
} );

// 访问：http://yoursite.com/?test_websocket=1

手动测试缓存失效

// 测试缓存失效
add_action( 'init', function() {
    if ( isset( $_GET['test_cache'] ) ) {
        $cache_invalidator = FD_WebSocket_Push_Cache_Invalidator::get_instance();
        $cache_invalidator->revalidate_tag( 'test-cache-tag' );
        wp_die( 'Cache invalidation test completed. Check logs.' );
    }
} );

// 访问：http://yoursite.com/?test_cache=1
