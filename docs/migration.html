迁移指南

迁移概述

本指南将帮助您从旧的 fd-pusher 插件平滑迁移到新的 fd-websocket-push 插件。新插件在功能上完全兼容旧版本，同时提供了更好的代码结构和可维护性。

✅

零功能丢失

所有原有功能都已完整迁移

🔧

零配置变更

使用相同的配置常量

🔄

向后兼容

提供全局函数包装器

📈

性能提升

更好的代码组织和效率

迁移前准备

1. 备份现有环境

  1. 备份数据库

    虽然迁移不涉及数据库变更，但建议进行完整备份

  2. 备份插件文件

    保留 fd-pusher 插件文件的副本，以备回滚使用

  3. 记录当前配置

    记录 wp-config.php 中的相关常量配置

  4. 测试当前功能

    确认旧插件的所有功能都正常工作

2. 环境检查

WordPress 版本 确保版本 ≥ 5.0
PHP 版本 确保版本 ≥ 7.4
必需常量 确认 FD_WEBSOCKET_PUSH_SECRET 和 REVALIDATE_SECRET 已定义
WebSocket 服务 确认 WebSocket 服务器正常运行
前端服务 确认 Next.js 前端应用正常运行

迁移步骤

步骤 1: 停用旧插件

  1. 进入插件管理

    在 WordPress 后台导航到 插件 → 已安装的插件

  2. 停用 fd-pusher

    找到 "FD Pusher" 插件，点击"停用"

  3. 确认停用

    检查插件状态显示为"未激活"

步骤 2: 安装新插件

  1. 上传新插件

    将 fd-websocket-push 文件夹上传到 /wp-content/plugins/

  2. 验证文件结构

    确认所有必需文件都已正确上传

  3. 检查权限

    确保文件权限设置正确

步骤 3: 激活新插件

  1. 激活插件

    在插件列表中找到 "FD WebSocket Push"，点击"激活"

  2. 检查激活日志

    查看错误日志确认插件成功激活

    [FD WebSocket Push] FD WebSocket Push plugin activated
  3. 验证配置

    确认插件能够正确读取配置常量

步骤 4: 功能验证

  1. 测试文章事件

    创建、编辑、发布文章，检查 WebSocket 事件是否正常发送

  2. 测试分类法事件

    创建、编辑标签和分类，验证相关事件

  3. 测试缓存失效

    检查前端缓存是否正确失效

  4. 测试支付事件

    如果使用支付功能，测试文章解锁事件

功能对比验证

核心功能检查清单

文章更新推送 ✅ 编辑文章时发送 post:updated 事件
文章发布推送 ✅ 新文章发布时发送 post:inserted 事件
文章删除推送 ✅ 删除文章时发送 post:deleted 事件
状态变化推送 ✅ 文章状态变化时发送相应事件
标签更新推送 ✅ 标签变化时发送 tag:updated 事件
分类更新推送 ✅ 分类变化时发送 category:updated 事件
自定义分类法推送 ✅ 自定义分类法变化时发送 taxonomy:updated 事件
支付解锁推送 ✅ 支付成功时发送 post:unlocked 事件
缓存标签失效 ✅ 自动失效相关的 Next.js 缓存标签
缓存路径失效 ✅ 自动失效相关的页面路径缓存

高级功能检查

ACF 字段支持 ✅ 支持 ACF 字段更新事件
权限级别推送 ✅ 根据文章访问权限确定推送目标
元数据过滤 ✅ 正确过滤内部和临时元数据
批量操作处理 ✅ 高效处理批量内容变更
错误处理 ✅ 完善的错误处理和日志记录

向后兼容性

全局函数兼容

新插件提供了向后兼容的全局函数，确保任何调用旧函数的代码继续正常工作：

fd_pusher_revalidate_tag() ✅ 自动映射到新的缓存失效方法
fd_pusher_revalidate_tag_for_term() ✅ 自动映射到新的分类法缓存失效方法

配置兼容

新插件使用完全相同的配置常量：

  • FD_WEBSOCKET_PUSH_SECRET - WebSocket 推送密钥
  • REVALIDATE_SECRET - 缓存失效密钥

迁移后清理

确认迁移成功

  1. 运行完整测试

    在生产环境中测试所有关键功能

  2. 监控日志

    观察几天的运行日志，确认没有错误

  3. 性能检查

    确认新插件没有影响网站性能

  4. 用户反馈

    收集用户反馈，确认前端功能正常

清理旧文件（可选）

⚠️ 注意

只有在确认新插件完全正常工作后，才考虑删除旧插件文件。建议保留备份至少一个月。

  1. 删除旧插件目录

    删除 /wp-content/plugins/fd-pusher/ 目录

  2. 清理数据库

    如果有相关的选项或元数据，可以选择清理

  3. 更新文档

    更新项目文档，反映新的插件名称和结构

回滚计划

如果在迁移过程中遇到问题，可以按以下步骤回滚：

  1. 停用新插件

    在插件管理页面停用 FD WebSocket Push

  2. 恢复旧插件

    重新激活 fd-pusher 插件

  3. 验证功能

    确认所有功能恢复正常

  4. 分析问题

    检查日志，分析迁移失败的原因

  • 错误日志中有成功激活的消息
  • WebSocket 事件正常发送
  • 前端缓存正确失效
  • 所有原有功能都正常工作
  • 网站性能没有下降
